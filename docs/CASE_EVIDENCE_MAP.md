# Case Evidence Map

The manuscript uses two author-supplied AI-assisted project archives as reflexive case materials. They are not treated as independently validated technical evidence.

## Case 1: Battery-model audit

Used as an example of an industrial-technology-oriented AI-assisted project that did not reach practical engineering claims.

Relevant internal material categories:

- README / repository orientation
- claim-boundary statement
- phase summaries concerning PyBaMM model comparison and residual-drift audit
- specialist handoff / expert-review questions
- final prohibited-claims list

Final interpretation in the manuscript:

> The project was reduced from a battery-technology-oriented ambition to a residual-drift audit of simplified models against external discharge data.

## Case 2: A10-derived Hubble-tension scaffold audit

Used as an example of a basic-science/cosmology-oriented AI-assisted project that did not reach physical or observational cosmology claims.

Relevant internal material categories:

- README / repository orientation
- claim-boundary statement
- terminal decision matrix
- expert-handoff summary
- no-go status for real-data likelihood, MCMC, posterior, and evidence comparison

Final interpretation in the manuscript:

> The project was reduced from a cosmological scaffold toward a failure-boundary archive after no first-principles physical E(z)/H(z) bridge was established.

## Cross-case pattern

Both cases follow the same pattern:

1. rapid creation of research-like artifacts;
2. apparent plausibility through domain vocabulary and formal structure;
3. grounding deficit when checked against domain requirements;
4. reduction to claim-boundary or failure-boundary records.
